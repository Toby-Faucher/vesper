# Vesper UI Redesign (Design System, Shell, Chat UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **UI tasks:** every implementer of a task that changes what the user sees (Tasks 1, 2 and 4 to 18) also uses the `frontend-design` skill (direction, type, composition) and the `impeccable` skill (critique, polish, hardening) before calling the task done. The rulings and tokens below win over anything those skills suggest.

**Goal:** Turn the working but bare web app into a calm, dark, Linear-style product: one token system with a single style switch point, a left sidebar with live voice presence, a small floating call bar, a Cmd/Ctrl-K switcher, a redesigned chat, onboarding, settings, admin screens and @mention notifications. No behaviour that works today is lost.

**Architecture:** Colours, type, radii and motion live as CSS custom properties in `web/src/styles/tokens.css`, under one selector per style (`[data-style='vesper']` on `<html>`). Tailwind v4 maps role names to those properties with `@theme inline`, and the default Tailwind palette is switched off, so a component can only use roles. Primitives are native platform elements (`<dialog>`, the Popover API, `<input type="range">`, checkboxes with `role="switch"`) wrapped in small Svelte components. The voice call moves out of `Room.svelte` into a module store (`lib/voice.svelte.ts`) so the call outlives route changes; a path router in `session.svelte.ts` drives the shell. Server, protocol and `web/src/lib/audio/` are not changed.

**Tech Stack:** Svelte 5.57.3, TypeScript 6.0.3, Vite 8.3.5, Tailwind 4.3.3, vitest 5.0.5, playwright-core 1.64.1. One new package: `animejs` 4.5.0 (only `waapi.animate` is imported). One package removed: `bits-ui` (installed, never imported).

**Spec:** `docs/superpowers/specs/2026-10-30-vesper-design.md` (Stack, Rooms and voice presence, Text chat, Build order step 5), `docs/ui-design.md` (principles, binding), `docs/superpowers/plans/2026-11-01-app-backend.md` (the API this plan consumes; see `docs/architecture.md` for the route table). Toby's decisions for this redesign (accent, layout, colour rules, notifications, admin, settings) were given to the planner on 2026-11-01 and are restated in the Rulings marked **[Toby]**.

**Inputs read by the planner:** the current `web/src` and `web/e2e`, the UI audit (13 screenshots at 1440x900, main at 2dd7958) and three research notes (voice UX, chat UX, visual). Their useful points are folded into the tasks; the notes are not in the repo.

**Precondition:** the backend plan's Tasks 1 to 17 are merged on `feat/app-v1` (they are as of 51d9f9d). This plan needs no server change. If a task finds it needs one, it stops and reports instead of editing `crates/`.

## Global Constraints

- **`web/src/lib/audio/` is not edited.** UI may import from it and read `Capture.getStats()`, `DenoiseMode`, `AudioSettings`. Capture order and the fallback chain stay as they are.
- **No server, protocol or `gen/` change.** Every screen uses routes listed in `docs/architecture.md`.
- **Colours only through tokens.** No hex, `rgb()`, `oklch()` or Tailwind palette class (`neutral-`, `red-`, `amber-`, `sky-`, `green-` ...) in any `.svelte` or `.ts` file outside `web/src/styles/tokens.css`. A test enforces it (Task 1).
- **One switch point.** `data-style` on `<html>` is the only place a style is chosen. Components never read it.
- **Per-user colour only on avatars and the speaking ring.** Never on names, text, borders of rows or message bodies. No role-coloured names.
- **No Discord look-alikes:** no server rail, no right-hand member column, no `#` before room names, no role colours, no blurple or purple, no rounded-square server icons, no "voice connected" panel docked in the sidebar.
- **Dark only, desktop only** (Chrome and Firefox). Minimum supported viewport 1024x640; design and screenshots at 1440x900.
- **Motion:** only on state changes, 100 to 220 ms, ease-out `cubic-bezier(0.2, 0, 0, 1)`, only `opacity` and `transform`. Nothing loops. Nothing animates because a person is speaking except an instant ring toggle. Under `prefers-reduced-motion: reduce`, movement becomes a 100 ms opacity change or nothing.
- **Copy:** short plain sentences, no em dashes, no `#` room prefix, errors from tables (never a raw code or `err.message`). `scripts/check-wording.sh` passes.
- **No `{@html}` and no `innerHTML`** (`no-raw-html.test.ts` stays green).
- **Tests:** vitest runs in the node environment; no DOM testing library is added. Logic goes in plain `.ts` modules with unit tests; what the user sees is checked with Playwright in `web/e2e/` and with screenshots.
- **Every task ends with:** `npm --prefix web run ci` (svelte-check, vitest, build, size), `scripts/check.sh wording`, `npm --prefix web run e2e` (needs `scripts/capped.sh cargo build --release -p vesper-server` once and `npm --prefix web run build`), and `npm --prefix web run shots -- <task scenes>` for visible tasks. Commit only the task's files; never `git add -A`.
- **e2e labels are a contract.** Each task lists the labels and selectors the e2e scripts rely on. A task that changes one updates `web/e2e/*.mjs` in the same commit and says so in the commit body.
- **Size budget:** see the Rulings (the 2026-11-01 one replaces the first). `web/scripts/size-check.mjs` fails when, in gzip, the first load JS (the entry chunk in `dist/index.html`, its modulepreloads and every chunk they import statically) passes 70 kB, any single lazy chunk passes 35 kB, all JS together passes 150 kB, or all CSS passes 14 kB. Each task looks for savings first and says its first load and summed numbers in the commit.

## Review Focus

UI review checklist. The reviewer of every visible task and the final QA task walk it with the screenshots open.

1. **Hierarchy.** One primary action per view (amber fill); everything else is ghost or subtle. The room name and the timeline win over chrome. The sidebar is quieter than the main pane.
2. **Spacing rhythm.** Every gap, padding and size is a multiple of 4 px. Rows in one list share one height. No one-off margins to nudge something into place.
3. **One type scale.** Only the six sizes and two weights in the Rulings. No text below 12 px. Numbers that change (counts, times, stats) use tabular figures.
4. **Contrast.** Body text 4.5:1 or more, UI parts and focus rings 3:1 or more, checked by `tokens.test.ts`; tertiary text never on hover or selected surfaces.
5. **Focus rings.** Every interactive element shows the amber `:focus-visible` ring (2 px, offset 2 px), including inside dialogs and popovers; nothing removes `outline` without replacing it.
6. **Keyboard paths.** From sign in to joining voice, sending a message, replying, searching, opening settings, revoking an invite: each works without a mouse. Dialogs trap focus and return it to the opener; popovers close on Esc and return focus.
7. **States.** Every list and fetch has an empty, loading and error state with plain text (Ruling on errors). No spinner without a cause. Missing data shows a dash and a short reason.
8. **Honest status.** Connected, reconnecting, speaking, muted, force-muted, the noise suppression mode and its fallback reason are shown only from real signals.
9. **Reduced motion.** With `prefers-reduced-motion: reduce` nothing slides or scales; the screenshot scene `reduced-motion` proves it.
10. **No layout shift.** Hover toolbars overlay, never push. Unread pills, typing lines and status lines reserve their height. Images reserve space from their stored size or a fixed max box.
11. **Size budget.** `npm run size` passes; the commit says the measured numbers.
12. **Not a Discord look-alike.** None of the items in Global Constraints. Compare the shell screenshot against that list.
13. **Colour rules.** Per-user colour only on avatars and rings; amber only for primary actions, focus, selection markers, mentions and the unread line.
14. **Copy.** Plain, short, no `#`, no codes, no em dashes; buttons say what they do ("Join voice", "Revoke", "Copy link").
